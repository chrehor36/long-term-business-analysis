# ADDENDUM 2026-10-06: the OSIS and BCC runs quote framework wording beside a ledger id

**Operator rule 6.** The run files are not edited; this addendum corrects the record.

**The runs.**
- `Test Runs/2026-10-05 Run - OSIS OSI Systems.md`, line 361: "a castle whose future cannot be judged" and the tenuous
  moat **[M2000-019]** to TOO HARD.
- `Test Runs/2026-10-06 Run - BCC Boise Cascade.md`, line 312: not a castle "whose future cannot be judged" (TOO HARD
  **[M2000-019]**).

**What is wrong.** The quoted words, "whose future cannot be judged", are the framework's own phrasing of section I's
TOO HARD box, not words of the cited row. The row M2000-019 reads, verbatim: "When we don’t have a — when we see a moat
that’s tenuous in any way — getting back to your question — it’s just too risky. We don’t know how to valuate that, and
therefore we leave it alone." Placing the id beside the framework's quoted words reads as if the row said them. This is
the same class of error as `Test Runs/ADDENDUM 2026-10-05 - SONY run, two framework sentences cited as rows.md`.

**What it changes.** Nothing in either box. In both runs the id was cited for the routing (a tenuous moat goes to
TOO HARD), which the row supports in its own words ("a moat that’s tenuous in any way", "We don’t know how to
valuate that"). Both runs closed OUT at Q2 on other evidence, and neither rests on this sentence.

**The correct reading.** Read each sentence as: the framework's phrase, in quotation marks, is the framework's; the
row M2000-019 is cited for the rule that a tenuous moat, which "We don’t know how to valuate", is left alone.

**Found by** the main session's citation check after the BCC run was committed; the OSIS instance had been passed at
the time as a near miss. Future briefs already say never to place an id beside the framework's own wording.
